1. Point Alertmanager at the gateway
--------------------------------------------------------------------------
Add this receiver to your Alertmanager configuration:

    receivers:
      - name: remedik
        webhook_configs:
          - url: http://{{ include "remedik.fullname" . }}-gateway.{{ .Release.Namespace }}.svc:{{ .Values.gateway.port }}{{ .Values.gateway.path }}
{{- if not .Values.gateway.auth.disabled }}
            http_config:
              authorization:
                type: Bearer
                credentials: <the token in Secret {{ include "remedik.gatewayTokenSecret" . }}, key {{ .Values.gateway.auth.secretKey }}>
{{- end }}

Route the alerts you want remediated to that receiver.

If you run the Prometheus Operator, an AlertmanagerConfig object does this
without touching your monitoring release — QUICKSTART.md has it, including the
part that catches everybody: the operator adds a namespace= matcher to every
route it generates, so a route defined in the monitoring namespace only ever
matches alerts about that namespace, and nothing arrives.
{{ if .Values.gateway.auth.disabled }}
WARNING: gateway authentication is disabled. Anything that can reach the
service can ask remedik to act. Use this for local development only.
{{- end }}

2. Add a strategy
--------------------------------------------------------------------------
Strategies decide what happens for which alert. A first one:

    apiVersion: remedik.dev/v1alpha1
    kind: RemediationStrategy
    metadata:
      name: pod-crashloop
    spec:
      trigger:
        match:
          alertname: KubePodCrashLooping
      guards:
        cooldown: 15m
        maxPerHour: 4
      steps:
        - action: deployment.restart
      onFailure:
        retries: 1

Actions enabled in this release: {{ include "remedik.enabledActions" . | default "none — every action is disabled, so no strategy can do anything" }}

Each one is a permission: what it may touch, and why, is listed in the
chart's action-rbac.yaml. Enable more with, for example,
--set actions.podDelete.enabled=true

4. Read the dashboard
--------------------------------------------------------------------------
The dashboard is served on a ClusterIP Service; this chart creates no
Ingress, because who may see your alert labels and workload names is your
decision, not the chart's. Reach it with a port-forward:

    kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "remedik.fullname" . }}-dashboard {{ .Values.dashboard.port }}:{{ .Values.dashboard.port }}

Then open http://127.0.0.1:{{ .Values.dashboard.port }}/
{{- if not .Values.dashboard.auth.disabled }}

Your browser will ask for credentials. Leave the username empty and paste
the token as the password — it is in Secret {{ include "remedik.dashboardTokenSecret" . }}, key {{ .Values.dashboard.auth.secretKey }}:

    kubectl -n {{ .Release.Namespace }} get secret {{ include "remedik.dashboardTokenSecret" . }} -o jsonpath='{.data.{{ .Values.dashboard.auth.secretKey }}}' | base64 -d
{{- else }}

WARNING: the dashboard is served without authentication. Anything that can
reach the port can read every alert label, namespace and workload name
remedik has recorded. Use this for local development only.
{{- end }}
{{- else }}

The read-only dashboard is not installed. Enable it with
--set dashboard.enabled=true --set dashboard.auth.token=<value>
{{- end }}
