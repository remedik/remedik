Kubernetes auto-remediation operator · Apache-2.0

The runbook you have typed forty times should not need you at 3am.

It is 03:00 and payments-api is crash-looping again. Somebody is paged, opens a runbook, reads three lines, types kubectl rollout restart, and goes back to bed.

That work is mechanical. What has kept it manual is not difficulty — it is that handing a robot write access to production is a decision nobody wants to sign off on.

remedik is built for that signature. It turns Alertmanager alerts into remediation you can audit, bound and switch off — and it does nothing at all until you say so.

No agent. No SaaS. No data leaves your cluster. No LLM in the execution path.

Why you can actually run it

Every one of these is a property you can check, not a promise in a README.

structural

It does nothing by default

Dry-run is the install default, and it is not a flag inside the code that acts. Actions implement Plan and Execute as separate methods, so a simulated run never reaches the mutating one. Read the reports for a week before you change anything.

per namespace

Adoption is not all-or-nothing

Act in staging, report only in prod, from one install. The posture is decided when the record is created and written onto it, so every execution says which one it ran under.

rbac

Permissions follow features

The chart grants a permission only because a named action needs it. Enable nothing and remedik can read. A test in the pipeline fails if that stops being true.

audit

Every action explains itself

Each execution records the plan, the kubectl a human would have typed, what changed, and whether it worked. An incident review reads the record, not the logs.

guards

The blast radius is bounded first

Cooldowns, an hourly ceiling, and a guard that refuses to touch the last healthy replica. A guard that cannot evaluate refuses rather than allows.

escalation

When it fails, somebody is told

A second plan runs when a remediation fails for good. If that fails too, the record says so — because “we tried to tell you and could not” is the thing you need to find later.

A strategy is a resource you keep in git

No DSL, no UI-only state, nothing that exists in one person’s browser.

strategy.yaml

apiVersion: remedik.dev/v1alpha1
kind: RemediationStrategy
metadata:
  name: pod-crashloop
spec:
  trigger:
    match:
      alertname: KubePodCrashLooping
  guards:
    cooldown: 15m       # not again this soon
    maxPerHour: 4       # a storm cannot amplify
    blastRadius:
      minAvailable: 1   # never the last replica
  steps:
    - action: deployment.restart
  onFailure:
    retries: 1
    steps:              # and if that fails, page
      - action: webhook.call
        with:
          url: https://events.pagerduty.com/v2/enqueue
          secretRef: pagerduty-routing-key

install

helm install remedik \
  oci://ghcr.io/remedik/charts/remedik \
  --namespace remedik --create-namespace \
  --set gateway.auth.token="$(openssl rand -hex 24)"

# Dry-run is on. Nothing is changed until you
# have read a week of this:
kubectl get remediations -n remedik

verify what you are running

cosign verify ghcr.io/remedik/remedik:v0.1.0 \
  --certificate-identity-regexp \
    '^https://github.com/remedik/remedik/' \
  --certificate-oidc-issuer \
    https://token.actions.githubusercontent.com

Multi-arch images signed with cosign keyless, an SBOM attested to the image, every CI action pinned to a commit SHA. No key to protect and nothing to take on trust.

Not published yet. The tags that exist are release candidates and their packages are private. v0.1.0 is the first one meant to be installed; until then it builds and runs from a checkout.

See what it would have done

A read-only dashboard, off by default. Built from a read-only client and refusing anything but GET before it routes — read-only by construction rather than by intention.

What it costs

Nothing, and there is nothing to buy. remedik is Apache-2.0 and stays that way: nothing is held back for a paid tier, there is no telemetry, and no feature is behind a licence key.

Worth more than money

Tell us it runs in production. One line — “we run this on N clusters” — is what makes the next person’s security review shorter. Report the near-misses. Contribute a strategy to the cookbook.

Read it before you trust it

It asks for write access to your cluster, so the promises it makes are written down as invariants, and the reasoning behind each is in the repository beside the code that keeps it.

Try it on something disposable

One command builds a throwaway cluster, a real Prometheus, a workload that really breaks, and remedik recording what it would do about it. Nothing is simulated and nothing of yours is touched.
